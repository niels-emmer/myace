## Purpose

Keep Go tests readable, deterministic and race-clean.

## When to use it

When adding tests, fixing a flaky test, or reviewing a change whose tests rely on sleeps or shared state.

## Checklist

- **Tables**: named cases in a slice, run each with `t.Run`; mark parallel-safe cases with `t.Parallel`.
- **Helpers**: call `t.Helper`; use `t.Cleanup` for teardown and `t.TempDir` for files.
- **Fakes over mocks**: define small interfaces at the consumer and use hand-written fakes; avoid heavy mock frameworks unless the project already uses one.
- **Time**: inject a clock or use short deadlines through context, never `time.Sleep` to wait for another goroutine.
- **Concurrency**: assert with channels, `WaitGroup` or `errgroup`; run with `-race` and, for suspected leaks, a goroutine-leak check.
- **HTTP**: use `httptest` for handlers and servers; do not call real services.
- **Golden files**: keep them small, reviewed, and regenerated by an explicit flag.

## Expected output

Tests that fail only when behaviour changes and that stay green under the race detector.

# Developer Writing

## Never Invent An Event

<!-- myace: priority=90 tags=writing,integrity -->

Do not state or imply a meeting, a discussion, a decision, or anything else the reader did not see or hear about. State only work that was done and facts that were checked. Do not attribute your reasoning to the team, and do not describe how you checked when nobody asked.

Style for review replies, PR descriptions, commit subjects and chat messages (brevity, plain words, no filler, no dash connectors) lives in the `developer-voice` and `review-and-commit-wording` skills, loaded when you write that kind of text. Style never overrides attribution: follow any project rule that marks AI-authored work.
